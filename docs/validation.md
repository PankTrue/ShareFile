# Проверка backend

Дата: 4 октября 2026 года. Среда локальной проверки — macOS ARM64, Go 1.26.8. Реальное устройство KN-1811 и KeenDNS в этой проверке не использовались.

## Выполненные проверки

- `go test ./...`: интеграционные сценарии с настоящей SQLite и временными директориями HDD; unit-проверки безопасной конфигурации, инициализации, архива и ограниченного логирования.
- `go test -race ./...`: проверки конкурентных chunks и остальные сценарии без выявленных data races.
- `go vet ./...`: без замечаний.
- `GOOS=linux GOARCH=arm64 GOARM64=v8.0 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w'`: успешная сборка, `file` определяет ELF AArch64, статически связанный. Размер около 12 МиБ; это размер исполняемого файла, не потребление RAM.
- `govulncheck v1.8.0` для host и целевого Linux ARM64: 0 уязвимостей в используемых пакетах/вызовах. Единственная запись уровня модуля — [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) для неподдерживаемого `golang.org/x/crypto/openpgp`; приложение его не импортирует. Из x/crypto используются Argon2id и его Blake2b-зависимость.
- OpenAPI JSON: разрешаются все внутренние references; все явно зарегистрированные HTTP API маршруты присутствуют в контракте. Tus методам, зарегистрированным через общий handler, также соответствуют операции контракта. Это структурная проверка, отдельный сторонний OpenAPI validator не запускался.
- `sh -n` для init-скрипта и service/run, `git diff --check`: без ошибок. Пакеты Entware и supervision на роутере ещё не запускались.

## Проверенное поведение

API-тесты проверяют cookie/CSRF и чужой Origin, private-only административные маршруты, личные папки, наследование групповых прав, неизменность отзыва ссылки после повторной выдачи доступа и перемещения, отключение аккаунта/устройства, одноразовое pairing, запрет отключения последнего администратора.

Для файлов проверены обрыв и durable offset, повтор creation с Idempotency-Key, конкурентные записи в один offset, аварийное состояние после rename до commit, повторный recovery, expiry, отсутствие доступа к незавершённым/чужим uploads, HTTP Range, совпадения имён, явная замена, trash/restore и durable purge. Очистка папки включает ранее удалённые вложенные объекты. Отзыв и purge проверены также на количестве записей больше одного batch.

64-битные offsets и Range проверены на sparse checkpoint за отметкой 5 ГиБ. Этот тест не передаёт по сети полный файл 5 ГиБ и не заменяет испытание настоящего большого файла на роутере.

Публичные ссылки проверены для файла и живого дерева папки, с парольной cookie, Range, экранированием HTML-имён, отзывом и запретом перехода к объектам вне поддерева. Импорт сохраняет исходник, отклоняет выбранные symlinks и внешние пути. Проверки storage включают потерю корня, недопущение fallback, нехватку места, отказ инициализировать каталог с существующими неуправляемыми данными. Backup не допускается внутри data_dir, в том числе через symlink; restore отклоняет небезопасные имена/ссылки и существующее назначение.

## Проверка отдельного процесса

После сборки host-бинарника из корня репозитория:

```sh
python3 scripts/smoke-test.py
```

Скрипт создаёт временное хранилище и тестового администратора, слушает только свободные loopback-порты. Проверены реальные публичный/приватный listeners, process lock и отказ backup при запущенном сервере; обрыв TCP PATCH на 70 000 байтах; сохранение offset после SIGTERM/restart; докачка и совпадение SHA-256 файла 2 МиБ; Range; публичная ссылка; graceful shutdown и offline CLI backup/restore с совпадением содержимого.

В sandbox этой машины запрещены локальные sockets, поэтому процессный smoke-test выполнен с разрешёнными loopback-сокетами. Все тестовые данные и процессы удалены после проверки. Настройки роутера, системные сервисы и пользовательские файлы не менялись.

## Проверки, оставшиеся для развёртывания

Фактические KeeneticOS/kernel, файловая система/mount HDD, Direct/Cloud, доступность loopback backend для KeenDNS, приватный TLS и firewall, boot/autostart/supervision, USB hotplug, внешние PATCH/HEAD/Range и настоящий файл больше 4 ГБ, измерения RSS/CPU и влияния на маршрутизацию. Результат локальной ARM64-сборки подтверждает архитектуру бинарника, а не успешный запуск на роутере.

Полный Web UI и desktop-клиенты ещё не реализованы. Стартовая конфигурация изменяется через JSON/restart; через административный API меняется срок незавершённых uploads. Удаление/переименование групп, изменение admin-роли существующего аккаунта, file ACL overrides и версии файлов остаются вне текущего API.
