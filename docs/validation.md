# Проверка backend, Web UI и macOS

Дата: 4 октября 2026 года. Среда локальной проверки — macOS ARM64, Go 1.26.8. Реальное устройство KN-1811 и KeenDNS в этой проверке не использовались.

## Выполненные проверки

- `go test ./...`: интеграционные сценарии с настоящей SQLite и временными директориями HDD; unit-проверки безопасной конфигурации, инициализации, архива и ограниченного логирования.
- `go test -race ./...`: проверки конкурентных chunks и остальные сценарии без выявленных data races.
- `go vet ./...`: без замечаний.
- `GOOS=linux GOARCH=arm64 GOARM64=v8.0 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w'`: успешная сборка, `file` определяет ELF AArch64, статически связанный. Размер около 12 МиБ; это размер исполняемого файла, не потребление RAM.
- `govulncheck v1.8.0` для host и целевого Linux ARM64: 0 уязвимостей в используемых пакетах/вызовах. Единственная запись уровня модуля — [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) для неподдерживаемого `golang.org/x/crypto/openpgp`; приложение его не импортирует. Из x/crypto используются Argon2id и его Blake2b-зависимость.
- OpenAPI JSON: разрешаются все внутренние references; все явно зарегистрированные HTTP API маршруты присутствуют в контракте. Tus методам, зарегистрированным через общий handler, также соответствуют операции контракта. Это структурная проверка, отдельный сторонний OpenAPI validator не запускался.
- `sh -n` для init-скрипта и service/run, `git diff --check`: без ошибок. Пакеты Entware и supervision на роутере ещё не запускались.

## Проверенное поведение

API-тесты проверяют cookie/CSRF и чужой Origin, private-only административные маршруты, личные папки, наследование групповых прав, неизменность отзыва ссылки после повторной выдачи доступа и перемещения, отключение аккаунта/устройства, одноразовое pairing, запрет отключения последнего администратора.

Для файлов проверены обрыв и durable offset, повтор creation с Idempotency-Key, конкурентные записи в один offset, аварийное состояние после rename до commit, повторный recovery, expiry, отсутствие доступа к незавершённым/чужим uploads, HTTP Range, совпадения имён, явная замена, trash/restore и durable purge. Очистка папки включает ранее удалённые вложенные объекты. Отзыв и purge проверены также на количестве записей больше одного batch.

64-битные offsets и Range проверены на sparse checkpoint за отметкой 5 ГиБ. Этот тест не передаёт по сети полный файл 5 ГиБ и не заменяет испытание настоящего большого файла на роутере.

Публичные ссылки проверены для файла и живого дерева папки, с парольной cookie, Range, экранированием HTML-имён, отзывом и запретом перехода к объектам вне поддерева. Импорт сохраняет исходник, отклоняет выбранные symlinks и внешние пути. Проверки storage включают потерю корня, недопущение fallback, нехватку места, отказ инициализировать каталог с существующими неуправляемыми данными. Backup не допускается внутри data_dir, в том числе через symlink; restore отклоняет небезопасные имена/ссылки и существующее назначение.

## Проверка отдельного процесса

После сборки host-бинарника из корня репозитория:

```sh
python3 scripts/smoke-test.py
```

Скрипт создаёт временное хранилище и тестового администратора, слушает только свободные loopback-порты. Проверены реальные публичный/приватный listeners, process lock и отказ backup при запущенном сервере; обрыв TCP PATCH на 70 000 байтах; сохранение offset после SIGTERM/restart; докачка и совпадение SHA-256 файла 2 МиБ; Range; публичная ссылка; graceful shutdown и offline CLI backup/restore с совпадением содержимого.

В sandbox этой машины запрещены локальные sockets, поэтому процессный smoke-test выполнен с разрешёнными loopback-сокетами. Все тестовые данные и процессы удалены после проверки. Настройки роутера, системные сервисы и пользовательские файлы не менялись.

## React Web UI

Проверено локально: Node.js 24.19.0, React/React DOM 19.3.0, TypeScript 6.0.3, Vite 8.3.2. Версии зафиксированы в package.json и package-lock.json.

- `npm run build`: TypeScript и production-сборка проходят. Статика около 321 КБ целиком; JavaScript около 294 КБ, CSS около 26 КБ. Vite оценивает gzip JS+CSS примерно в 95 КБ; Go сейчас отдаёт обычные файлы без gzip middleware. На роутере выполняется только Go, React работает в браузере.
- `npm run check`: TypeScript, ESLint и 8 Vitest-проверок проходят. Сценарии проверяют ограниченные chunks, Unicode, same-origin Location, потерю ответов создания/записи, Idempotency-Key, загрузку после перезагрузки состояния, отказ продолжать с другим файлом, паузу in-flight запроса, пустые файлы и замену из локального файла с другим именем.
- `npm audit --omit=dev`: 0 известных уязвимостей runtime-зависимостей на дату проверки.
- Настоящий Chromium с Go backend и временной SQLite: вход/выход, приватная админка, пользователи, группа/состав, назначение reader/manager и видимость действий, передача файла 2,3 МБ несколькими chunks и SHA-256, анонимная ссылка, переименование/перемещение, реальная потеря ответа после durable chunk и продолжение после reload/повторного выбора исходника с проверкой SHA-256, замена с сохранением имени/отзывом прежней ссылки, корзина/восстановление, browser pairing/отзыв устройства, настройки TTL и импорт. Мобильная верстка 390×844 без горизонтального переполнения, меню открывается и скрывается. Публичный административный API возвращает 404 и для администратора. Нет JS-ошибок и CSP-нарушений.
- Браузерные результаты и снимки сохраняются в игнорируемый `web/test-results/`. Проверки используют только случайные loopback-порты, одноразовые аккаунты и временное хранилище. Данные пользователя и роутер не меняются.
- Добавлены Go-проверки effective_role, manager-only каталога пользователей/групп, имён прямых назначений и совместной регистрации SPA/служебных API/Tus. Полный `go test -race ./...` прошёл; после исправления регистрации статики повторно прошёл `go test -race ./internal/httpapi`. ARM64-бинарник пересобран.

Запуск и детали — [web-ui.md](web-ui.md). Глобальный поиск, деревья загрузок, архивы скачивания и desktop-приложения в этот этап не входят.

## Проверки, оставшиеся для развёртывания

Фактические KeeneticOS/kernel, файловая система/mount HDD, Direct/Cloud, доступность loopback backend для KeenDNS, приватный TLS и firewall, boot/autostart/supervision, USB hotplug, внешние PATCH/HEAD/Range и настоящий файл больше 4 ГБ, измерения RSS/CPU и влияния на маршрутизацию. Результат локальной ARM64-сборки подтверждает архитектуру бинарника, а не успешный запуск на роутере.

React Web UI и macOS-клиент реализованы; Linux/Windows ещё не реализованы. Стартовая конфигурация изменяется через JSON/restart; через административный API меняется срок незавершённых uploads. Удаление/переименование групп, изменение admin-роли существующего аккаунта, file ACL overrides и версии файлов остаются вне текущего API.

## Go desktop-ядро и macOS

Среда: macOS 27.0.1 Apple Silicon, Go 1.26.8, Apple Swift 6.3.2 (режим Swift 5), Command Line Tools. Минимальный target UI macOS 13.0. UI и helper успешно скомпилированы для `arm64` и `x86_64`, `lipo` подтверждает обе архитектуры. Intel и macOS 13.0 пока проверены только компиляцией, без запуска на этих системах.

- В `clients/core/` прошли `go vet ./...` и `go test -race ./...`: доверенный origin, запрет authenticated redirects, сохранённый idempotency key при потере creation response, потеря PATCH response и продолжение с серверного offset, отмена контекста/рестарт из checkpoint, отказ с изменённым исходником, sparse-файл больше 5 GiB, отзыв устройства, отсутствие автоматических повторов share. Sparse-тест передаёт последние байты большого файла и проверяет 64-битные offsets, а не всю длину 5 GiB.
- Universal bundle подписан локально ad-hoc; `codesign --verify --deep --strict` проходит. Размер приложения около 14 MiB, zip около 5,7 MiB. Это размеры на диске; RAM на реальном роутере не измерялась. Desktop на роутер не устанавливается.
- `ShareFile --self-test`: Finder pasteboard с несколькими Unicode-путями, запись/чтение/удаление уникальной тестовой записи Keychain, отсутствие публичной ссылки в сериализованном job, восстановление незавершённой очереди на паузе, блокирование автоматического повторного share после неопределённого результата и 64-битный размер.
- `scripts/desktop-smoke.py`: настоящий backend на случайных loopback-портах, одноразовый аккаунт, browser approval device request, Go bearer-клиент. TCP POST-override PATCH обрывается после 70 000 байт; backend останавливается и запускается вновь. Клиент продолжает из старого idempotency key без сохранённого creation response; ID файла совпадает, объект в папке один, итоговый SHA-256 совпадает. Unicode, пустой файл, публичная/парольная ссылка и отзыв устройства проверены.
- Сквозной тест нативного Swift Model запускает ту же очередь и process bridge, что использует UI, с двумя файлами и реальным Go helper/backend. Оба файла и ссылки проверяются через API, сохранённое состояние не содержит device token или публичных URL, ошибка недоступного источника видна в модели. Пользовательские настройки, Keychain и clipboard в этом сценарии не используются.
- Интерактивно через macOS UI проверены запуск окна, экран настроек, запрет внешнего HTTP с понятной ошибкой. В настоящем Finder у тестового Unicode-файла показан пункт «Службы → ShareFile: Загрузить и поделиться»; вызов передал файл приложению и показал настройку подключения. Finder не ожидал сетевой передачи. Test-файл не загружался на пользовательский сервер; окно тестовой папки закрыто.

Работа с реальным KeenDNS, реальным хранилищем пользователя и системным TCC-диалогом отказа в доступе требует отдельной проверки в целевом окружении. Процессный тест использует временные файлы и loopback; sandbox требует разрешения на локальные sockets. Установка в `~/Applications`, Developer ID и notarization не выполнялись. Инструкция — [macos.md](macos.md).
