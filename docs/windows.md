# ShareFile для Windows

Нативный клиент на C# и .NET 10: WPF с системной Fluent-темой, CommunityToolkit.Mvvm и Microsoft.Extensions.DependencyInjection. Протокол, очередь и сохранение состояния находятся в отдельном `ShareFile.Core`; Windows-интеграции и интерфейс — в `ShareFile.Windows`. Go helper не нужен, backend и macOS-клиент не изменены.

## Установка

Пакеты: `clients/windows/build/ShareFile-Windows-win-x64.zip` и `ShareFile-Windows-win-arm64.zip`. Выберите архитектуру компьютера, распакуйте **весь** архив и запустите `Install.cmd`. Приложение и .NET runtime входят в пакет; устанавливать .NET отдельно не требуется. Целевая система — Windows 11; совместимость с Windows 10 22H2 требует отдельной проверки на этой системе.

Установка выполняется для текущего пользователя без прав администратора:

- Приложение: `%LOCALAPPDATA%\Programs\ShareFile`.
- Ярлык: Start → ShareFile.
- Проводник: **Show more options → Send to → ShareFile - Upload and share**.
- Очередь: `%LOCALAPPDATA%\ShareFile\state.json`.

Закройте ShareFile через меню значка в трее перед обновлением. Установщик сохраняет предыдущую версию приложения в соседний каталог с датой, сохраняет очередь и учётные данные. Для автозапуска используйте `Install.cmd -StartWithWindows`: запись создаётся только в `HKCU`, запуск происходит в фоне. Обычная установка автозапуск не добавляет.

`Install.cmd` запускает PowerShell-скрипт с разрешением его выполнения только для этого процесса. Постоянная Execution Policy не меняется. Пакет пока не подписан Authenticode; цифровая подпись и проверка SmartScreen остаются задачей выпуска.

## Подключение и загрузка

1. В **Настройки** укажите HTTPS-адрес ShareFile без пути, логина и параметров. Адрес должен совпадать с серверным `public_url`: ссылка подтверждения устройства проверяется на тот же origin. HTTP разрешён только для loopback-разработки.
2. Нажмите **Подключить через браузер**, войдите в Web UI и подтвердите компьютер. Клиент соблюдает интервал опроса API, минимум 12 секунд. Пароль аккаунта приложение не получает.
3. По умолчанию выбраны `Uploads`, срок 7 дней и отсутствие пароля. В настройках доступны папки с правами управляющего, срок 1–365 дней, бессрочные ссылки и пароль 12–256 байт UTF-8.
4. Выберите файлы или **Загрузить папку…**, перетащите их в окно или передайте через **Send to**. Каталог занимает одну запись очереди: вложенность и пустые подпапки сохраняются, после завершения создаётся одна ссылка на корень. Максимум 100 записей в очереди.

Для локального CA роутера импортируйте доверенный публичный `lan-ca.pem` через Windows Certificate Import Wizard в **Current User → Trusted Root Certification Authorities**. Клиент использует обычную проверку TLS; исключений для недоверенных сертификатов нет. Импортируйте только CA вашего сервера.

Проводник передаёт всё выделение одной группе. По умолчанию окно не открывается, загрузка идёт в фоне, все готовые ссылки копируются по одной на строку, затем появляется одно уведомление через значок в трее. При ошибке буфера обмена уведомление сообщает об ошибке; ссылки можно скопировать из очереди. Если хотя бы один файл завершился с ошибкой, после обработки всей группы приходит одно уведомление с числом ошибок; ссылки успешно обработанных файлов доступны в очереди. Если компьютер ещё не подключён, открываются настройки; выбранные пути ожидают подтверждения в памяти.

**Сохранить настройки** сохраняет переключатели фоновой загрузки и уведомлений. Уведомления могут подавляться настройками Windows или Do Not Disturb; копирование продолжает работать. Закрытие окна оставляет приложение в трее. **Выход** приостанавливает очередь. После перезапуска незавершённые записи остаются на паузе: выберите запись и нажмите **Продолжить**.

Отдельные запуски `ShareFile.exe --upload "C:\path\one.txt" "C:\path\two.txt"` передают файлы существующему экземпляру через ограниченный по размеру named pipe с `CurrentUserOnly`. Второй процесс ожидает подтверждение приёма. `ShareFile.exe --background` запускает приложение без окна. Значок в трее открывает очередь и позволяет выйти.

## Надёжность и безопасность

- Один worker передаёт файлы последовательно. Состояние записывается атомарно через временный файл и flush до отправки запросов, требующих checkpoint. Ошибка сохранения прекращает передачу.
- Сохранённый случайный idempotency key предотвращает дубликаты при потере ответа создания загрузки. После каждого чанка и обрыва клиент получает durable offset через `HEAD`; локальный offset не считается подтверждением передачи.
- Чанки отправляются потоком, до 4 MiB, с `POST` и `X-HTTP-Method-Override: PATCH`. Файл целиком не читается в память; размеры и offsets — `long`. Повторы ограничены и учитывают `Retry-After`; 401/403/507 не повторяются автоматически.
- Перед возобновлением проверяются путь, размер, время изменения и SHA-256 выборок начала, середины и конца. Это проверка случайной замены источника, а не полный хеш всего файла. Во время передачи проверяются размер/время; Windows file handle запрещает одновременную запись через обычные файловые API.
- Токен и необязательный пароль ссылки хранятся в **Windows Credential Manager** текущего пользователя. JSON очереди не содержит токен, пароль или URL публичной ссылки. HTTP redirects отключены; ошибки не включают URL запросов или тела ответов.
- Очередь привязана к серверу и ID аккаунта. С непустой очередью переключение на другой сервер или аккаунт запрещено.
- Создание публичной ссылки никогда не повторяется автоматически. Потеря ответа либо выход во время создания приводит к **Проверьте ссылки в Web UI**. Проверьте и при необходимости отзовите неизвестную ссылку перед созданием новой.

Готовые URL хранятся в памяти до выхода. После перезапуска используйте **Новая ссылка**. **Отозвать ссылку** отзывает последний известный share; остальные ссылки управляются в Web UI. **Отменить / убрать** удаляет незавершённую загрузку на сервере после подтверждения API; для завершённого файла удаляется только запись очереди. Если серверная отмена не подтверждена, checkpoint сохраняется. Во время передачи сначала нажмите **Пауза для всех** и дождитесь остановки.

**Отключить компьютер** удаляет локальный токен, сохраняя очередь. Для отзыва разрешения на сервере удалите устройство в Web UI → Аккаунт → Устройства. `Uninstall.cmd` удаляет установленное приложение, принадлежащие ему ярлыки и автозапуск. Очередь, Credential Manager и серверные файлы сохраняются; перед полным удалением отмените незавершённые загрузки и отзовите устройство.

## Сборка и проверки

Нужен .NET SDK 10; стабильный feature band выбирает `global.json`. Все внешние пакеты закреплены версиями и `packages.lock.json`. Официальные компоненты: [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100), [MVVM Toolkit](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/mvvm/), [Dependency Injection](https://learn.microsoft.com/en-us/dotnet/core/extensions/dependency-injection). Очередь использует небольшой атомарный JSON checkpoint, поэтому SQLite/EF Core здесь не нужны. Передача использует BCL `HttpClient` и явные правила повтора, чтобы случайно не повторить создание ссылки. Тесты — [xUnit.net v3 с Microsoft Testing Platform](https://xunit.net/docs/getting-started/v3/getting-started).

Из корня репозитория на macOS/Linux:

```sh
make windows-compile
make windows-check
make windows-smoke
```

`windows-smoke` сначала собирает Go backend, затем запускает все тесты C#-ядра с временным диском и тестовым аккаунтом. Без `SHAREFILE_BACKEND` интеграционный тест явно пропускается. Пользовательские сервер, очередь, учётные данные и буфер обмена не используются.

На Windows из `clients/windows`:

```powershell
dotnet restore ShareFile.slnx --locked-mode
dotnet build ShareFile.slnx -c Release --no-restore
dotnet test --project tests/ShareFile.Core.Tests/ShareFile.Core.Tests.csproj --no-restore
dotnet test --project tests/ShareFile.Windows.Tests/ShareFile.Windows.Tests.csproj --no-restore
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

`build.ps1` создаёт автономные ZIP x64/ARM64 и SHA-256 файлы в `build/`. Проверка checksum:

```powershell
Get-FileHash .\build\ShareFile-Windows-win-x64.zip -Algorithm SHA256
```

Workflow **Windows client** проверяет C#-ядро с настоящим Go backend на Linux: сервер использует Unix API и не собирается для Windows. Затем Windows job компилирует решение, проверяет Credential Manager, передачу нескольких Unicode-путей между экземплярами, создание/показ/скрытие WPF-окна и portable-тесты ядра; после этого публикует Actions artifact **ShareFile-Windows** с обеими архитектурами. Workflow не публикует GitHub Release автоматически.

Локально на macOS подтверждены: сборка всех четырёх проектов без предупреждений, автономная компиляция Windows x64/ARM64 и 30 тестов C#-ядра, включая настоящий backend, рестарт/возобновление, ссылки с паролем и отзыв, пустые/Unicode-файлы, sparse-источник больше 5 GiB, отсутствие секретов в JSON, одно уведомление об ошибках группы и запрет перенаправления токена. Sparse-тест проверяет offsets больше 4 GiB, а не полную передачу большого файла.

Запуск самого приложения на Windows, реальные баннеры/буфер обмена, вызов Send to, установка/обновление, ARM64 runtime и внешняя сеть KeenDNS/KN-1811 пока не подтверждены. Windows-тесты добавлены в CI; его первый запуск ещё требуется.

Папка может содержать до 10 000 объектов с вложенностью до 128 уровней. Символьные ссылки, junction и специальные файлы внутри дерева отклоняются. При продолжении сверяются дерево и отпечатки файлов; изменённую папку нужно добавить заново. Создание каталогов использует сохранённые ключи идемпотентности; обрыв ответа не создаёт дубли. Состояние вложенных файлов сохраняется атомарно, законченные файлы повторно не передаются.
