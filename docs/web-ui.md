# React Web UI

`web/` — самостоятельный frontend-пакет: React 19, TypeScript, Vite. Runtime-зависимости — React и React DOM. Компоненты, CSS и SVG-иконки локальные; внешние шрифты, CDN, аналитика и SSR не используются. Production — статический `web/dist/`, который обслуживает Go-сервер. На Keenetic не нужны Node.js или дополнительный web-сервис.

## Запуск

На машине разработчика нужен Go 1.26+ и Node.js 24 LTS (либо совместимый Node 22.12+). Из корня:

```sh
make build
make web-build
python3 scripts/configure-local.py
backend/bin/sharefile init-storage -config local-config.json
backend/bin/sharefile admin-create -config local-config.json -username admin
backend/bin/sharefile serve -config local-config.json
```

`configure-local.py` создаёт конфиг с абсолютным `web_dir`, существующий файл не перезаписывает. Если конфиг уже есть, указать в нём `web_dir` со значением `/absolute/path/to/ShareFile/web/dist`. Примерная локальная БД находится в `/tmp/sharefile-local`: для постоянных данных выбрать отдельную директорию на диске и уникальную метку до инициализации.

Открыть `http://127.0.0.1:8080` для файлов и `http://127.0.0.1:8081` для администрирования. На приватном входе требуется администратор. Публичная учётная запись администратора не открывает меню админки; её API там возвращает 404.

Во время разработки Go продолжает работать на 8080/8081. Из `web/`:

```sh
npm ci
npm run dev
```

Пользовательский Vite: `http://127.0.0.1:5173`. Для админки во втором терминале:

```sh
cd web
npm run dev:admin
```

Административный Vite: `http://127.0.0.1:5174`. Development proxy изменяет Origin на соответствующий loopback backend origin и слушает только loopback. Production отдаёт интерфейс и API с одного origin, проверяет настоящий Origin и CSRF и не использует Vite proxy.

## Действия

- «Мои файлы»: личная папка, вложенные папки, скачивание, переименование, перемещение, замена и корзина. «Доступные папки» показывает другие доступные папки; администратор может создать общий корень.
- Загрузка: выбор или перетаскивание отдельных файлов, очередь, подтверждённый прогресс, пауза, продолжение, отмена. Передача последовательная частями не больше 4 МиБ и ограничения сервера. Файл целиком не читается в память.
- «Поделиться»: отдельные ссылки, срок 1/7/30 дней или без срока, необязательный пароль. Новый адрес показывается только при создании — его нужно скопировать. «Публичные ссылки» показывает собственные записи и позволяет отозвать их.
- «Доступ к папке»: поиск активных пользователей/групп, reader/editor/manager, изменение и удаление прямых назначений. Действующее разрешение наследуется и складывается по максимальной роли. Удаление прямого назначения не отменяет доступ из родителя, группы или владения.
- «Корзина»: восстановление в прежнюю или выбранную папку, необратимое удаление с подтверждением.
- «Устройства»: подтверждение запроса по `/device/connect?request=…` после входа, список и отзыв подключений. Подтверждение всегда явно выполняет пользователь.
- Приватная админка: создание пользователей, включение/отключение, сброс пароля, создание групп и состав, импорт-копирование файла и изменение срока незавершённых загрузок. Параметры запуска отображаются для чтения и меняются через конфиг с перезапуском.

Функции по роли скрываются, каждый API-запрос независимо проходит серверную авторизацию. Сессия и пароль не сохраняются в localStorage: сессия остаётся в HttpOnly cookie, CSRF — в памяти. Адреса публичных ссылок и device tokens Web UI также не сохраняет в браузерное хранилище. Статика работает с серверной CSP без разрешения inline-скриптов/стилей.

## Возобновление

При обрыве очередь показывает ошибку и кнопку продолжения; перед передачей браузер спрашивает серверный offset через HEAD. Потерянный ответ создания повторяется с прежним Idempotency-Key. Tus PATCH отправляется как POST с `X-HTTP-Method-Override: PATCH`; прохождение через реальный KeenDNS требуется проверить на устройстве.

После перезагрузки страницы браузер не имеет доступа к исходному File. Сохраняются только метаданные очереди отдельно для пользователя и текущего origin; нужно снова выбрать исходный файл. Проверяются имя, размер, lastModified и SHA-256 первых/последних 64 КиБ вместе с метаданными. Это проверка совпадения образцов, а не полная контрольная сумма большого файла. Для гарантированной сверки всего локального содержимого нужен отдельный клиент/будущее расширение протокола. Если localStorage запрещён, текущая очередь продолжает работать, но не переживает перезагрузку.

Завершённый upload подтверждается HEAD состоянием `complete`. Замена сохраняет прежнее имя, даже если локальный файл называется иначе. Старый объект уходит в корзину, его прямые ссылки отзываются. Если очередь истекла/объект недоступен, отменить запись и создать новую загрузку.

## Проверки

Из корня:

```sh
make web-check
cd web
npx playwright install chromium
cd ..
make browser-check
```

`web-check`: TypeScript, ESLint, Vitest. `browser-check`: Chromium и изолированный Go backend с временной SQLite/директорией и случайными loopback-портами. Пароли случайные; процесс и директория удаляются после проверки. Скриншоты — игнорируемый `web/test-results/`.

Размер production-сборки и результаты приёмки — [validation.md](validation.md). ARM64, HDD, длинные загрузки, TLS и KeenDNS проверяются отдельно по [deployment.md](deployment.md).

## Текущие границы

Фильтр ищет на текущей странице из 100 объектов; глобального поиска API пока нет. Загрузка деревьев папок и скачивание архивом не входят в этот этап. Существующие ссылки не восстанавливаются из hash. Удаление/переименование групп, смена admin-флага существующего пользователя и онлайн backup не поддержаны API. Конфигурационный файл, сертификаты и управление процессом не редактируются через web. Desktop-клиенты выпускаются отдельно.
