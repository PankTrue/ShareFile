# React Web UI

`web/` — самостоятельный frontend-пакет: React 19, TypeScript, Vite. Runtime-зависимости — React и React DOM. Компоненты, CSS и SVG-иконки локальные; внешние шрифты, CDN, аналитика и SSR не используются. Production — статический `web/dist/`, который обслуживает Go-сервер. На Keenetic не нужны Node.js или дополнительный web-сервис.

## Запуск

На машине разработчика нужен Go 1.26+ и Node.js 24 LTS (либо совместимый Node 22.12+). Из корня:

```sh
make build
make web-build
python3 scripts/configure-local.py
backend/bin/sharefile init-storage -config local-config.json
backend/bin/sharefile admin-create -config local-config.json -username admin
backend/bin/sharefile serve -config local-config.json
```

`configure-local.py` создаёт конфиг с абсолютным `web_dir`, существующий файл не перезаписывает. Если конфиг уже есть, указать в нём `web_dir` со значением `/absolute/path/to/ShareFile/web/dist`. Примерная локальная БД находится в `/tmp/sharefile-local`: для постоянных данных выбрать отдельную директорию на диске и уникальную метку до инициализации.

Открыть `http://127.0.0.1:8080` для файлов и `http://127.0.0.1:8081` для администрирования. На приватном входе требуется администратор. Публичная учётная запись администратора не открывает меню админки; её API там возвращает 404.

Во время разработки Go продолжает работать на 8080/8081. Из `web/`:

```sh
npm ci
npm run dev
```

Пользовательский Vite: `http://127.0.0.1:5173`. Для админки во втором терминале:

```sh
cd web
npm run dev:admin
```

Административный Vite: `http://127.0.0.1:5174`. Development proxy изменяет Origin на соответствующий loopback backend origin и слушает только loopback. Production отдаёт интерфейс и API с одного origin, проверяет настоящий Origin и CSRF и не использует Vite proxy.

## Действия

- «Мои файлы»: личная папка, вложенные папки, скачивание, переименование, перемещение, замена и корзина. «Доступные папки» показывает другие доступные папки; администратор может создать общий корень.
- Загрузка: выбор или перетаскивание файлов и папок, очередь, подтверждённый прогресс, пауза, продолжение, отмена. Передача последовательная частями не больше 4 МиБ и ограничения сервера. Файл целиком не читается в память.
- «Поделиться»: отдельные ссылки, срок 1/7/30 дней или без срока, необязательный пароль. Новый адрес показывается только при создании — его нужно скопировать. «Публичные ссылки» показывает собственные записи и позволяет отозвать их.
- «Поделиться папкой» в открытой папке создаёт ссылку на её живое содержимое. Получателю не нужна учётная запись: доступны вложенные папки, предпросмотр фото (JPEG, PNG, GIF, WebP, BMP) и текста в UTF-8, отдельное скачивание. Текст ограничен первыми 256 КиБ; HTML и SVG отображаются как экранированный текст. Остальные форматы и другие кодировки доступны для скачивания. Предпросмотр сохраняет пароль, срок и границы ссылки.
- «Скачать всё (ZIP)» в открытой папке и на публичной странице скачивает весь текущий каталог, включая вложенные и пустые папки, независимо от фильтра и страницы списка. Архив содержит верхнюю папку с её именем и создаётся прямо в HTTP-потоке: сервер не пишет временный ZIP и не копирует содержимое файлов. Достаточно прав читателя; публичная ссылка сохраняет пароль, срок, отзыв и границы доступа. Архив занимает один слот скачивания. Размер заранее неизвестен; Range и возобновление ZIP не поддерживаются. При обрыве сети или ошибке чтения скачивание прерывается — запустите его заново. Содержимое живое, без снимка: изменения во время скачивания могут потребовать повторного запуска.
- «Доступ к папке»: поиск активных пользователей/групп, reader/editor/manager, изменение и удаление прямых назначений. Действующее разрешение наследуется и складывается по максимальной роли. Удаление прямого назначения не отменяет доступ из родителя, группы или владения.
- «Корзина»: восстановление в прежнюю или выбранную папку, необратимое удаление с подтверждением.
- «Устройства»: подтверждение запроса по `/device/connect?request=…` после входа, список и отзыв подключений. Подтверждение всегда явно выполняет пользователь.
- Приватная админка: создание пользователей, включение/отключение, сброс пароля, создание групп и состав, импорт-копирование файла и изменение срока незавершённых загрузок. Все параметры JSON-конфига редактируются в «Настройках»: диск и абсолютная директория хранения, метка, резерв, лимиты передач, адреса/URL, пути TLS, Web UI, журнал и источники импорта.

Функции по роли скрываются, каждый API-запрос независимо проходит серверную авторизацию. Сессия и пароль не сохраняются в localStorage: сессия остаётся в HttpOnly cookie, CSRF — в памяти. Адреса публичных ссылок и device tokens Web UI также не сохраняет в браузерное хранилище. Статика работает с серверной CSP без разрешения inline-скриптов/стилей.

## Настройки сервера

В приватной админке открыть «Настройки». Список подключённых дисков показывает mount, устройство, файловую систему и свободное место; кнопку «Обновить диски» можно использовать после подключения накопителя. Выбор диска подставляет `<mount>/sharefile`, абсолютную директорию можно изменить вручную. Родительский каталог должен существовать. Для смены метки хранилища требуется другая директория.

«Сохранить черновик» проверяет значения и сохраняет `<config>.pending` с правами `600`. Черновик переживает обычный перезапуск, но применяется только кнопкой «Применить и перезапустить» с подтверждением. «Удалить черновик» возвращает форму к действующим значениям. Изменения из другой вкладки или ручное редактирование активного JSON вызывают конфликт, не перезаписываются автоматически. Срок незавершённых загрузок сохраняется отдельно и применяется сразу.

При применении сервер останавливает приём запросов, ожидает завершения текущих (до 30 секунд), закрывает SQLite и перезапускает слушатели внутри того же процесса. Для другой директории копируются файлы, метаданные, аккаунты, ссылки, сессии и частичные загрузки; новая директория должна быть пустой или отсутствовать. Копирование идёт потоком с проверкой свободного места и резерва. Старые данные не удаляются. Во время переноса сервер недоступен; при прежнем origin страница обновится автоматически. При смене административного URL интерфейс показывает ссылку на новый адрес; cookies и CSRF туда не пересылаются запросами frontend.

При ошибке остаётся прежняя конфигурация и показывается причина. Если копирование уже завершилось, но последующее сохранение/запуск не удались, новая копия может остаться на диске: она не используется автоматически. Перед повторной попыткой выбрать другую пустую директорию. Не отключать исходный накопитель до окончания переноса и проверки файлов. Параметры TLS задаются путями к существующим сертификату/ключу, HTTP допустим только на loopback. Пустой `web_dir` отключает интерфейс; это явно указано при подтверждении.

API: `GET/PUT/DELETE /api/v1/admin/config`, `POST /api/v1/admin/config/apply`, `GET /api/v1/admin/volumes`. Они доступны только браузерному администратору на приватном listener; устройства не могут управлять конфигурацией. Числа: 1–1024 слота передачи, часть от 1 байта до 1 ГиБ, резерв от 0 до `Number.MAX_SAFE_INTEGER` байт.

## Возобновление

При обрыве очередь показывает ошибку и кнопку продолжения; перед передачей браузер спрашивает серверный offset через HEAD. Потерянный ответ создания повторяется с прежним Idempotency-Key. Tus PATCH отправляется как POST с `X-HTTP-Method-Override: PATCH`; прохождение через реальный KeenDNS требуется проверить на устройстве.

После перезагрузки страницы браузер не имеет доступа к исходному File. Сохраняются только метаданные очереди отдельно для пользователя и текущего origin; нужно снова выбрать исходный файл. Проверяются имя, размер, lastModified и SHA-256 первых/последних 64 КиБ вместе с метаданными. Это проверка совпадения образцов, а не полная контрольная сумма большого файла. Для гарантированной сверки всего локального содержимого нужен отдельный клиент/будущее расширение протокола. Если localStorage запрещён, текущая очередь продолжает работать, но не переживает перезагрузку.

Завершённый upload подтверждается HEAD состоянием `complete`. Замена сохраняет прежнее имя, даже если локальный файл называется иначе. Старый объект уходит в корзину, его прямые ссылки отзываются. Если очередь истекла/объект недоступен, отменить запись и создать новую загрузку.

## Проверки

Из корня:

```sh
make web-check
cd web
npx playwright install chromium
cd ..
make browser-check
```

`web-check`: TypeScript, ESLint, Vitest. `browser-check`: Chromium и изолированный Go backend с временной SQLite/директорией и случайными loopback-портами. Пароли случайные; процесс и директория удаляются после проверки. Скриншоты — игнорируемый `web/test-results/`.

Для проверки в уже установленном Chrome вместо Chromium: `cd web && PLAYWRIGHT_CHANNEL=chrome npm run test:browser` (используется временный профиль).

Размер production-сборки и результаты приёмки — [validation.md](validation.md). ARM64, HDD, длинные загрузки, TLS и KeenDNS проверяются отдельно по [deployment.md](deployment.md).

## Текущие границы

Фильтр ищет на текущей странице из 100 объектов; глобального поиска API пока нет. Загрузка деревьев папок и скачивание архивом не входят в этот этап. Существующие ссылки не восстанавливаются из hash. Удаление/переименование групп, смена admin-флага существующего пользователя и онлайн backup не поддержаны API. Сертификаты и ключи указываются путями к существующим файлам; их создание и загрузка через web не поддерживаются. Desktop-клиенты выпускаются отдельно.

## Загрузка папки целиком

Управляющий может перетащить каталог из Finder в область файлов или нажать «Загрузить папку». Вложенность сохраняется; одно дерево отображается одной записью в очереди с общим прогрессом. Когда завершены все файлы, автоматически создаётся одна ссылка на папку на 7 дней без пароля. Адрес виден в очереди: «Скопировать ссылку». Для других срока или пароля откройте загруженную папку и «Поделиться папкой».

Перетаскивание сохраняет и пустые каталоги, включая полностью пустой корень. Кнопка выбора использует webkitdirectory/FileList: браузер передаёт относительные пути файлов, но не пустые каталоги. Для них используйте перетаскивание. Обход читает все порции readEntries, включая каталоги с более чем 100 непосредственными детьми. [Документация браузерного API](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemDirectoryReader/readEntries).

Лимит — 10000 объектов и 128 компонентов пути в одном каталоге. Общий размер должен помещаться в безопасное целое JavaScript. Передача идёт теми же ограниченными tus-частями. Пауза и отмена работают для всего дерева. Отмена незавершённой загрузки переносит созданное дерево в корзину. Отдельная загрузка с тем же именем получает собственную папку с суффиксом и не смешивается с прежними файлами.

После перезагрузки страницы выберите тот же каталог в очереди или перетащите его в прежнюю папку назначения. Проверяются относительные пути, размеры, даты изменения и отпечатки файлов; завершённые файлы не передаются повторно. Для пустого дерева достаточно «Продолжить». Потерянные ответы создания папок восстанавливаются по сохранённым ключам без дубликатов. Если ответ создания ссылки потерян, запись остаётся в неопределённом состоянии: откройте загруженную папку, проверьте её ссылки перед созданием новой. Публичный адрес остаётся только в памяти страницы.
